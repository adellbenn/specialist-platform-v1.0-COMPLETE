## 🎯 نظرة عامة

### ما هو نظام الأدوار والصلاحيات (RBAC)؟

نظام **RBAC** (Role-Based Access Control) يسمح بـ:
```
✓ تعيين أدوار للمستخدمين
✓ تحديد صلاحيات لكل دور
✓ التحكم في الوصول للموارد
✓ الحماية من الوصول غير المصرح
```

### الفوائد:
```
🔒 أمان أعلى
📊 إدارة أسهل
🎯 تحكم دقيق
📋 توثيق واضح
```

## 👥 الأدوار والأوصاف

### 1. 🔐 Super Admin (مسؤول النظام)

**الكود:** `super_admin`

**الوصف:**
```
مسؤول النظام الأساسي - له صلاحيات كاملة على كل شيء
```

**الصلاحيات:**
```
✅ جميع الصلاحيات في النظام
✅ التحكم الكامل في جميع الموارد
✅ إدارة المستخدمين والأدوار
✅ إدارة قاعدة البيانات
✅ الوصول إلى جميع التقارير
```

**الاستخدام:**
```
- الرئيس التنفيذي (CTO/CEO)
- مدير النظام
- المطورون في بيئة الاختبار
```

**النطاق:**
```
📊 سيطرة كاملة على المشروع
```

---

### 2. 👔 Center Manager (مدير المركز)

**الكود:** `center_manager`

**الوصف:**
```
مدير المركز الصحي - يدير العمليات اليومية
```

**الصلاحيات الرئيسية:**
```
✅ لوحة التحكم (عرض + إحصائيات + الأداء)
✅ إدارة المستفيدين (إنشاء + تحديث + حذف + تعيين)
✅ إدارة الملفات (عرض + تحديث)
✅ إدارة المواعيد (عرض الكل + إنشاء + تحديث + إلغاء + تأكيد)
✅ إدارة الجلسات (عرض الكل + إنشاء + تحديث + تأكيد الحضور)
✅ إدارة التقارير (عرض الكل + إنشاء + تحديث + موافقة + تصدير)
✅ إدارة المدفوعات (عرض + إنشاء + تحديث)
✅ إدارة المستخدمين (عرض + إنشاء + تحديث + تعطيل)
✅ إدارة المركز (عرض)
✅ الملف الشخصي (عرض + تحديث الخاص به)
✅ الإشعارات (عرض)
✅ سجل التدقيق (عرض)
```

**النطاق:**
```
📊 إدارة المركز كاملاً
```

---

### 3. 👨‍💼 Supervisor (مشرف)

**الكود:** `supervisor`

**الوصف:**
```
مشرف - يراقب العمل ويوافق على التقارير
```

**الصلاحيات الرئيسية:**
```
✅ لوحة التحكم (عرض + إحصائيات + الأداء)
✅ عرض المستفيدين (الكل فقط)
✅ عرض الملفات
✅ عرض المواعيد (الكل فقط)
✅ عرض الجلسات (الكل فقط)
✅ عرض التقارير (الكل فقط)
✅ موافقة التقارير
✅ تصدير التقارير
✅ الملف الشخصي (عرض + تحديث الخاص به)
✅ الإشعارات (عرض)
```

**النطاق:**
```
👁️ مراقبة وموافقة فقط
```

---

### 4. 👨‍⚕️ Specialist (أخصائي)

**الكود:** `specialist`

**الوصف:**
```
أخصائي علاجي - يدير حالاته الخاصة
```

**الصلاحيات الرئيسية:**
```
✅ لوحة التحكم (عرض + إحصائيات)
   └── يرى بيانات حالاته فقط

✅ المستفيدون (حالاته فقط)
   ├── عرض حالاته
   ├── إنشاء حالة جديدة
   ├── تحديث بيانات حالة
   └── تعيين حالة لنفسه

✅ الملفات (حالاته فقط)
   ├── عرض ملفات حالاته
   └── تحديث الملفات

✅ المواعيد (مواعيده فقط)
   ├── عرض مواعيده
   ├── إنشاء موعد
   ├── تحديث موعد
   ├── إلغاء موعد
   └── تأكيد الموعد

✅ الجلسات (جلساته فقط)
   ├── عرض جلساته
   ├── إنشاء جلسة
   ├── تحديث الجلسة
   └── تأكيد الحضور

✅ التقارير (تقاريره فقط)
   ├── عرض تقاريره
   ├── إنشاء تقرير
   └── تحديث التقرير

✅ الملف الشخصي (خاص به)
   ├── عرض بيانته
   └── تحديث بيانته

✅ الإشعارات (عرض)
```

**النطاق:**
```
📊 بيانات شخصية + حالاته فقط
```

---

```
   ├── عرض جميع المستفيدين
   ├── إنشاء مستفيد جديد
   └── تحديث بيانات المستفيد

✅ المواعيد (الكل)
   ├── عرض جميع المواعيد
   ├── إنشاء موعد جديد
   ├── تحديث الموعد
   ├── إلغاء الموعد
   └── تأكيد الموعد

✅ الملف الشخصي (خاص به)
   ├── عرض بيانته
   └── تحديث بيانته

✅ الإشعارات (عرض)
```

**النطاق:**
```
📋 إدارة المستقبلة والمواعيد
```

### 6. ❌ Accountant (محاسب) - معطّل

**الكود:** `accountant`

**الحالة:** ⏸️ **معطّل حالياً**

**الوصف:**
```
محاسب - يدير المدفوعات والحسابات (سيتم تفعيله في مرحلة لاحقة)
```

**الصلاحيات (محفوظة):**
```
✅ لوحة التحكم (عرض + إحصائيات)

✅ المستفيدون (الكل - عرض فقط)

✅ المدفوعات
   ├── عرض جميع المدفوعات
   ├── إنشاء دفعة جديدة
   └── تحديث الدفعة

✅ التقارير (الكل)
   ├── عرض جميع التقارير
   └── تصدير التقارير

✅ الملف الشخصي (خاص به)
   ├── عرض بيانته
   └── تحديث بيانته

✅ الإشعارات (عرض)
```

**الحالة:**
```
⏸️ معطّل مؤقتاً
📦 البيانات محفوظة بأمان
🔄 يمكن تفعيله لاحقاً بدون فقدان البيانات
```

**النطاق:**
```
💰 إدارة المالية (معطّلة حالياً)
```

### 7. 👤 Beneficiary (مستفيد)

**الكود:** `beneficiary`

**الوصف:**
```
مستفيد من الخدمات - يرى بيانته ومواعيده فقط
```

**الصلاحيات الرئيسية:**
```
✅ البيانات الشخصية (نفسه فقط)
   ├── عرض بيانته
   └── تحديث بيانته

✅ الملفات (ملفه فقط)
   ├── عرض ملفه الطبي

✅ المواعيد (مواعيده فقط)
   ├── عرض مواعيده

✅ التقارير (المشاركة معه)
   ├── عرض التقارير المشاركة معه

✅ الإشعارات (عرض)
```

**النطاق:**
```
👁️ عرض محدود - بيانات شخصية فقط
```

## ⏸️ تعطيل الأدوار

### ما هي آلية التعطيل؟

```
✓ إبقاء البيانات القديمة
✓ منع المستخدمين من استخدام الدور
✓ إمكانية التفعيل لاحقاً
✓ عدم فقدان أي بيانات
```

### دور Accountant - معطّل حالياً

```
الحالة الحالية: ⏸️ معطّل

كيف يتم التعطيل:
1. إضافة flag: isDisabled = true
2. إضافة check في Backend Guards
3. إخفاء الدور من Frontend
4. عدم السماح بتعيين المستخدمين له

التأثير:
✗ لا يمكن إنشاء مستخدم جديد بهذا الدور
✗ لا يمكن تعديل دور المستخدم إلى accountant
✓ المستخدمون الموجودون يتم تعطيل حساباتهم
✓ البيانات تبقى محفوظة

التفعيل لاحقاً:
✓ إزالة flag isDisabled
✓ إضافة check في Frontend
✓ اختبار شامل
✓ تفعيل الحسابات
```

## 🔐 التحكم في الوصول

### كيفية التحقق من الصلاحيات؟

#### في Backend:

```typescript
// استخدام Guard للتحقق
@UseGuards(PermissionGuard('BENEFICIARY_VIEW_ALL'))
@Get('/beneficiaries')
async getAllBeneficiaries() {
  // ...
}

// أو استخدام Decorator
@AdminOnly()
@Get('/admin-panel')
async adminPanel() {
  // ...
}
```

#### في Frontend:

```typescript
// عرض شرطي بناءً على الصلاحية
{userPermissions.includes('BENEFICIARY_CREATE') && (
  <Button onClick={createBeneficiary}>
    إضافة مستفيد جديد
  </Button>
)}

// أو استخدام Hook
const canCreate = useCanAccess('BENEFICIARY_CREATE');
```

## 🔒 الأمان والحماية

### مبادئ الأمان:

```
1. Principle of Least Privilege
   ├── كل مستخدم يملك أقل صلاحيات ممكنة
   └── فقط ما يحتاجه لعمله

2. Defense in Depth
   ├── تحقق من Frontend
   ├── تحقق من Backend
   └── تحقق من Database

3. Audit & Logging
   ├── تسجيل كل محاولة وصول
   ├── تسجيل كل عملية حساسة
   └── مراجعة سجلات التدقيق بانتظام

4. Regular Review
   ├── مراجعة الصلاحيات بانتظام
   ├── إزالة الصلاحيات غير الضرورية
   └── تحديث السياسات
```

### نقاط الضعف والحماية:

```
⚠️ Privilege Escalation
   الحل: تحقق من الصلاحيات في كل عملية

⚠️ Unauthorized Access
   الحل: استخدم JWT Tokens

⚠️ Data Breach
   الحل: Encryption + Access Logging

⚠️ Accidental Changes
   الحل: Audit Trail + Versioning
```

## ❓ الأسئلة الشائعة

### س: كيف أضيف صلاحية جديدة؟

```
ج: اتبع الخطوات التالية:
   1. أضف الصلاحية في permissions.enum.ts
   2. أضف الصلاحية في role-permissions.ts
   3. أضف Guard/Decorator في الـ Backend
   4. أضف Check في الـ Frontend
   5. اختبر الصلاحية
   6. وثّق التغيير في CHANGELOG.md
```

### س: كيف أغيّر صلاحيات دور؟

```
ج: تعديل مباشر في role-permissions.ts:
   1. افتح الملف
   2. ابحث عن الدور
   3. أضف أو احذف الصلاحيات
   4. احفظ واختبر
```

### س: ماذا لو أخطأ المستخدم؟

```
ج: النظام سيرفع خطأ:
   ├── في Frontend: رسالة "ليس لديك صلاحية"
   ├── في Backend: HTTP 403 Forbidden
   └── في Logs: تسجيل محاولة الوصول غير المصرح
```

### س: كيف أعطّل دور؟

```
ج: 1. أضف flag isDisabled = true
   2. أضف check في Backend Guards
   3. أخفِ الدور من Frontend
   4. اختبر عدم إمكانية الوصول
```

### س: هل يمكن تفعيل دور معطّل؟

```
ج: نعم! ببساطة:
   1. أزل flag isDisabled
   2. أزل check من Guards
   3. اظهر الدور في Frontend
   4. اختبر التفعيل
   5. أعِد تفعيل الحسابات
```

## 📝 ملاحظات مهمة

```
⚠️ عند تغيير الصلاحيات:
   1. اختبر جميع الأدوار
   2. تحقق من الأمان
   3. وثّق التغيير
   4. أبلِغ الفريق
   5. قم بـ update الملفات

⚠️ الأدوار المعطّلة:
   1. يتم الاحتفاظ بالبيانات
   2. لا يمكن تعيين دور جديد
   3. يمكن تفعيلها لاحقاً
   4. البيانات تبقى آمنة

⚠️ الأمان:
   1. لا تغيّر الصلاحيات في Runtime
   2. استخدم Migrations للتغييرات الكبرى
   3. اختبر جميع السيناريوهات
   4. احتفظ بنسخة احتياطية
```
